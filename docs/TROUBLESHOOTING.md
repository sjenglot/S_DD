# S_DD Rev 1 troubleshooting

**Stop on a FAIL message.** Keep the original backup and HDD unchanged. Retain the unique scratch `sdd-*` directory and its `operations.log` until the cause is understood. Do not add force flags or manually clear NTFS dirty/check-required flags.

| Symptom | Safe response |
| --- | --- |
| `s_dd doctor` reports a missing command | On Ubuntu 24.04, install the packages in [UBUNTU_FIRST_RUN.md](UBUNTU_FIRST_RUN.md). `fdisk` supplies `sfdisk`; `ntfs-3g` supplies `ntfsresize` and `mkntfs`; `guestfs-tools` supplies `virt-resize`. Run `doctor` again. |
| Libguestfs appliance will not start | Run the included unprivileged `python3 -B tests/libguestfs_selftest.py` from the extracted release. Check the printed project-local temp/cache/runtime directories and the exact error. Ubuntu AppArmor, missing appliance dependencies, or permissions may differ from CachyOS; do not bypass confinement or proceed to the SSD while the file-based integration test fails. |
| Network backup works in a file manager but `sudo` cannot read it | User GVFS mounts are often unavailable to root. Arrange an IT-managed root-readable read-only system mount, or copy the `.img.gz` as the normal user to a new local file, verify both SHA-256 values, and use the local copy. Account for its compressed size in scratch free space. |
| Scratch required, on `/`, wrong filesystem, or insufficient | Confirm `findmnt -T "$SCRATCH"` reports a separately mounted local ext4, XFS, or Btrfs filesystem. Check `df -B1 "$SCRATCH"`. S_DD needs a full decompressed source, fitted output, and allowance simultaneously. It never formats or mounts scratch. |
| Source layout unsupported | V1 accepts exactly one MBR type-07 NTFS primary partition with 512-byte sectors. GPT, multiple partitions, BitLocker-like layouts, invalid NTFS metadata, and ambiguous images are refused. Preserve the source and use a different recovery plan. |
| `ntfsresize` says dirty, hibernated, bad sectors, or scheduled for check before shrinking | Preserve the original image. The first scratch resize must not force a pre-existing integrity problem. Diagnose on expendable copies or the original Windows system under an approved preservation procedure; do not clear flags just to make S_DD proceed. |
| `virt-resize` failure | Read `operations.log`. S_DD uses `--no-expand-content` because the preceding NTFS shrink schedules a Windows check. Do not add `--ntfsresize-force`; a new error needs investigation. Destination writing has not begun if fitting failed. |
| Target is mounted, has holders, is swap, or identity changed | Stop and reidentify every drive with `lsblk` and `/dev/disk/by-id`. Unmount only an identified expendable target on the work computer. Never select the system, backup, or scratch drive. |
| Process interrupted before `DESTINATION WRITE BEGINS NOW` | Destination has not been written by S_DD. Source remains unchanged. Retain scratch and logs, then investigate before any rerun. |
| Confirmation left blank or answered `n` | S_DD reports cancellation and retains the verified fitted image plus `job.json`. Run the printed `sudo s_dd resume /path/to/sdd-JOB` command to revalidate the same destination and confirm again; this avoids repeating decompression and shrinking. |
| `resume` refuses a job | Do not edit `job.json` or use a different drive. The fitted image must match its recorded SHA-256/layout, the job must remain in its scratch directory, and model, serial, and capacity must match the original destination. If any check fails, use the original source to start a fresh restore after investigating. |
| `sudo: s_dd: command not found` | A user-level executable under `~/.local/bin` may not be in sudo's secure PATH. Install system-wide with `sudo bash scripts/install_system.sh`; it installs under `/opt/s_dd` and `/usr/local/bin`, and refuses to overwrite an existing S_DD install. |
| Process interrupted after destination write begins | Target may be partial and must not be booted. Treat it as expendable, reidentify it, and restart a complete restore only when safe. Source and scratch remain. |
| Destination verification fails | Do not use the SSD. S_DD compares the fitted image to the actual target and checks target MBR/NTFS metadata; preserve the failed target and logs for diagnosis. |
| Windows runs CHKDSK on first boot | This is expected after `ntfsresize` marks the volume for a consistency check. Let it finish. A successful check still does not prove application, license, or instrument function. |
| Windows does not boot or instrument software fails | Keep the original HDD untouched. Preserve the SSD and scratch logs. Legacy BIOS geometry, bootloader, BCD, drivers, and licenses require separate diagnosis; S_DD's byte verification does not prove boot compatibility. |

The physical command is `s_dd`, never `sdd`. Follow the system-install instructions in [UBUNTU_FIRST_RUN.md](UBUNTU_FIRST_RUN.md) for reliable `sudo s_dd` invocation.
